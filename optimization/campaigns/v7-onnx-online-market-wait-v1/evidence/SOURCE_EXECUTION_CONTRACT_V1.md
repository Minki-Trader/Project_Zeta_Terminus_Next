# Original market-entry contracts

Facts from the exact frozen Optimization V7R baseline, read without execution or Live/broker access.

- Gate uses elapsed minutes and permits minute2 to reach signal evaluation, but the durable order-attempt cutoff is exactly `decision_bar+120seconds`. `MarkDecisionOrderAttempted` rejects `TimeCurrent()>deadline`; equality is allowed. A30second route therefore requires its entire wait to fit in that original cutoff.
- `DecisionIntent` is one global synchronous journal. Signal decision and `last_decision_bar` are saved before any broker action; order-attempt stage is also saved first. Another unresolved signal journal blocks the next signal. Core persistence stores only stage/component/bar/direction/signal/deadline/attempted/adopted-ticket; additional struct plan fields are not all durable. Restart clears the existing journal without replay.
- Current `OpenComponent` synchronously builds, persists, submits, observes, validates and adopts one market entry. It has no deferred queue. The parent strategy finalizes that journal after the call. A conditional native implementation must persist its own deferred decision completely while keeping this global synchronous submission contract coherent.
- Ordinary market-component broker pending orders are rejected by current ownership. Only the strict stop-fill transition and protected Passive US100 BUY_LIMIT/SELL_LIMIT singleton are normal broker-order cases. This campaign's proposed wait is an internal deferred market decision, never a new broker pending type or a reuse of Passive state.
- Passive reserves its planned risk while pending/cancel-pending and moves that reservation into a position on verified fill. Existing expiration/cancel/recovery, RC4 shadow, own position checks and all original management remain original. Deferred market execution must reevaluate actual risk/margin at submission; no inferred liquidity or earlier source headroom authorizes an order.

Principal paths under `optimization/baseline/NEXT-E03-V7R-RLO1-0bba2ca045fe/MQL5/Include/ZetaTerminusNext/`: `Strategies/ZetaStrategyShared.mqh`, `Execution/ZetaOrders.mqh`, `Execution/ZetaOwnership.mqh`, `Persistence/ZetaStateAndEvents.mqh`, `Strategies/ZetaPassive.mqh`, `Execution/ZetaProtectionAndReconciliation.mqh`.

The [official tick API](https://www.mql5.com/en/docs/python_metatrader5/mt5copyticksrange_py) accepts numeric epoch seconds and returns raw tick arrays. The producer passes those numeric native coordinates without timezone conversion. API UTC documentation does not override this project's separately anchored broker server-clock semantics. [Explicit initialization](https://www.mql5.com/en/docs/python_metatrader5/mt5initialize_py) supports an exact executable path and portable mode; the exporter checks both terminal and data paths before any historical quote request.
